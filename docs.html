Setup, settings and the privacy model

Quick start

ContribMatch is a static site: HTML, CSS and ES modules. There is no build step and no bundler. Clone the repository and serve the folder over HTTP, because ES modules and fetch do not work from file://.

bash
git clone https://github.com/contribmatch/contribmatch.git
cd contribmatch
python3 -m http.server 8080
# open http://localhost:8080

Any static server works — npx serve, caddy file-server, or GitHub Pages. The site uses relative links, so it also works from a sub-path such as https://<user>.github.io/contribmatch/.

Connect a local model with Ollama

Ollama runs open-weight models on your own machine. Gemma 3 is the default because it is small, multilingual and follows the JSON instruction format.

bash
ollama serve
ollama pull gemma3:4b
curl http://localhost:11434/api/tags

Then choose Ollama in the settings below and press Save.

Allow the browser to reach the daemon

Ollama's default CORS policy rejects browser requests from a page served on a different origin. Set the allowed origins before you start the daemon:

bash
OLLAMA_ORIGINS="http://localhost:8080,http://127.0.0.1:8080" ollama serve

If you deploy ContribMatch to GitHub Pages, add that origin too, for example OLLAMA_ORIGINS="https://your-user.github.io". If the daemon refuses the connection, the app keeps working: every agent falls back to its rule-based answer and says so under the results.

Connect Google AI Studio

Google AI Studio hosts Gemma and needs an API key. The key is typed into the browser and kept in sessionStorage, so it disappears when the tab closes. It is never written to localStorage, never logged and never sent anywhere except to Google.

!

A key pasted into a web page is visible to anyone who can use that browser profile. Use a key with the smallest scope that works, rotate it if the machine is shared, and never commit a key to a repository.

  1. Create a key in Google AI Studio.
  2. Paste it into the API key field below.
  3. Choose Google AI Studio and a Gemma model, then Save.

GitHub access

A token with no scopes is enough. It is kept in sessionStorage only.

Why add a GitHub token

Unauthenticated GitHub API requests are limited to 60 per hour, and search is limited further. A token raises the limit and gives you the exact contribution calendar.

The token needs no scopes: ContribMatch only reads public data. It is stored in sessionStorage and is sent only to api.github.com.

Local model timing and origins

The first call to a local model includes loading it into memory; on a CPU-only machine a single call can take one to five minutes. ContribMatch waits up to 5 minutes per model call and asks Ollama to keep the model resident (keep_alive: 30m), so follow-up calls in the same session are much faster.

If you serve the site from an origin other than http://localhost, start Ollama with OLLAMA_ORIGINS=* (or your exact site origin) so its CORS preflight is accepted — otherwise the matcher quietly falls back to rule scores.

Rate limits, queuing and caching

ContribMatch keeps GitHub usage low in three ways, and tells you what it is doing while it does it.

  • One request at a time. Every GitHub request from every page and agent runs through a single queue with a short pause between requests. Identical requests made at the same moment are collapsed into one. There is a small fixed cap on queued requests, and the queue reports itself on the matcher page.
  • A local issue catalogue. The matcher starts from a periodically refreshed list of open, beginner-labelled issues (data/issues.json), so most visitors never trigger a live search. When the catalogue is fresh you make no GitHub search requests at all; the chip above the results shows when it was last refreshed.
  • Caching with honest labels. Search results are reused for 5 minutes, profiles and repository metadata for 15 minutes. If GitHub is throttling, the app serves your last cached copy and flags it — it never shows old data as fresh, and it never invents results.

When GitHub really does refuse, the page says which limit ran out (core REST, search or GraphQL) and when it resets. Rate limits can never be fully ruled out — the goal of this design is to make them rare and harmless, not to promise they cannot happen.

Exact and approximate contribution data

The activity graph has three modes, and the label under the graph always says which one you are looking at.

  • Exact — uses the GitHub GraphQL contribution calendar, which covers the last year. It needs a token. Add one and the label changes to Exact.
  • Approximate — counts your public events (/users/<login>/events/public). That covers roughly the last 90 days and at most 300 events, so it is not the full year. The label reads Approximate and the note says so in full.
  • Sample — synthetic data shown before a username is entered and in sample mode. It is labelled Sample everywhere it appears.

Event types map to the four buckets like this: PushEvent to commits (counted with the number of commits in the payload), PullRequestEvent to pull requests, IssuesEvent and IssueCommentEvent to issues, and PullRequestReviewEvent and PullRequestReviewCommentEvent to reviews.

Privacy model

  • There is no backend. ContribMatch serves static files and nothing else.
  • Your GitHub token and AI Studio key live in sessionStorage.
  • Your shortlist lives in localStorage and can be cleared from the shortlist page.
  • The model only receives the issue title, body and labels of the shortlist, plus your inferred skills.
  • With Ollama, that request never leaves your machine.
  • ContribMatch never posts a comment, a branch or a pull request.

Troubleshooting

The matcher says the model is unavailable

Ollama is probably not running, or it is refusing the browser origin. Check curl http://localhost:11434/api/tags, then start it with OLLAMA_ORIGINS set to the origin serving ContribMatch. The app keeps working without the model — every agent has a rule-based fallback.

GitHub says the rate limit is reached

Add a read-only token in the settings above and switch the matcher to use it. Results are cached in localStorage for a few minutes, so repeating the same search does not spend more of your limit.

The graph looks empty

In approximate mode only the last 90 days are covered, so a quiet month can look empty. Add a token for the exact calendar, and check the label under the graph to see which mode you are in.

The page is blank and the console shows a module error

Serve the folder over HTTP rather than opening the file directly. Browsers block ES modules and fetch on file:// origins.
